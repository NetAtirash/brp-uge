# GitHub Releases and Foundry VTT installation

The GitHub repository is the **source of truth** for BRP UGE. Runtime ZIPs and the matching `system.json` release manifest are generated by GitHub Actions instead of being manually uploaded from ChatGPT.

## Publishing prerequisites

The repository currently uses the `brp-uge` Foundry system ID and Foundry V14.

**Important privacy restriction:** If this GitHub repository remains **Private**, its GitHub Release asset URLs are not anonymously downloadable. Foundry's normal **Manifest URL** installer requires publicly reachable URLs. Do not change the repository's visibility without reviewing its assets and licensing.

Supported paths:
- **Public distribution:** Switch this repository to **Public** after reviewing code, textures, fonts and licenses, or publish identical verified release artifacts to a separate **Public** distribution repository and update the manifest/download URLs to that public host.
- **Private testing:** Keep the repo Private and manually install the ZIP downloaded by a logged-in collaborator. The normal Foundry Manifest URL will not provide passwordless updates from a Private GitHub Release.

This repository does **not** automatically change visibility or publish assets to a different repository.

## Release workflow

1. Merge the release-pipeline pull request into `main`.
2. Confirm GitHub Actions is enabled and the `Release BRP UGE for Foundry VTT` workflow exists under Actions.
3. Confirm `system.json` has the intended release version, e.g. `1.21.5`; use the same value in the release Tag with a `v` prefix: `v1.21.5`.
4. Update `system.json` and changelog whenever creating future versions.
5. In GitHub Desktop, fetch/pull `main` after merging. Choose **Repository → Open in Terminal**, and run:

```bash
git checkout main
git pull --ff-only origin main
git tag v1.21.5
git push origin v1.21.5
```

6. GitHub Actions runs JavaScript checks and regression tests, builds `brp-uge.zip`, and publishes a GitHub Release with **both** `brp-uge.zip` and `system.json`. Do not manually publish a GitHub Release using the same tag while this workflow is creating it.
7. Confirm Actions is green and verify the Release assets exist before trying to install from Foundry.

The release workflow needs `contents: write` for its job's `GITHUB_TOKEN`. This permission is declared in `.github/workflows/release.yml`. If your organization restricts Actions, review the repository's **Settings → Actions → General**.

## Installation from Foundry (public release assets only)

Under **Game Systems → Install System**, use the Manifest URL:

```text
https://github.com/NetAtirash/brp-uge/releases/latest/download/system.json
```

This becomes usable **only when** a GitHub Release has published `system.json` and `brp-uge.zip` to a **publicly downloadable location**. This repository was Private when this release pipeline was configured.

The released manifest's `download` points to its own **version-pinned** asset:

```text
https://github.com/NetAtirash/brp-uge/releases/download/v1.21.5/brp-uge.zip
```

When publishing a new version, the build script updates that version-specific URL in the *released* manifest automatically. The manifest URL stays stable across releases.

## Safeguards

- A tag must match `system.json.version` exactly (for example, tag `v1.21.5` requires version `1.21.5`).
- The build checks the system ID and referenced runtime assets before it can publish.
- The ZIP has exactly one top-level `brp-uge/` directory; developer tests and GitHub workflow files are excluded.
- `Validate BRP UGE` runs the packaging check on pull requests. The tag-triggered release repeats all tests before publishing.
- Builds do **not** change World or Actor data and include **no Compendium datasets**.

## Local validation

```bash
python3 scripts/build_release.py --tag v1.21.5 --output dist
```

Inspect `dist/system.json` and `dist/brp-uge.zip`. These are generated outputs, not source files. Do not commit `dist/`.
